# 踩坑清单（阶段 6 质量门）

分析完成前，逐条过一遍：

| # | 检查项 | 失败示例 |
|---|---|---|
| 1 | 机制先于分析 | 把 session_search（搜历史日志）当"记忆检索" → 整段结论作废 |
| 2 | 全量口径核算 | Batch2 填 9,959 工具调用，实为 163 子集；全量是 13,735 |
| 3 | 统计写入成功率 | 只数 add/replace 次数，漏掉 73% 失败（容量溢出 = 最严重问题） |
| 4 | 正常现象不当发现 | 把"事后补记"写成问题 |
| 5 | 结论→证据→含义 | 堆数字没结论，或只有结论没证据 |
| 6 | 每个数字可复算 | 手工统计、不可追溯 |
| 7 | 跨批对比前查复杂度 | Batch1(13 调用/会话) vs Batch2(49) 直接比浪费率 → 错误结论 |
| 8 | 归因与观察分离 | "缺先查后写"是推断，不是测量 |
| 9 | 结论边界写清 | 平台不同、非严格对照 → 严格成立的结论只说"机制在位下单轮零写入" |
| 10 | 敏感数据不外传 | 含内网 IP/token/uid 的报告禁入公开仓库 |

## 验证手段

- **可复算**：`scripts/analyze.py` 重跑应产出相同 stats.json；
- **交叉核对**：关键数字（会话数/工具调用/memory 调用）与原始目录 `wc -l`、`grep -c` 对得上；
- **机制核对**：tools 含 memory 工具？system_prompt 含快照？成功/失败比例？
