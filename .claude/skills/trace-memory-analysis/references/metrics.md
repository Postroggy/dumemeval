# Memory 行为指标定义（阶段 4/5）

所有指标必须出自 `scripts/analyze.py`（可复算）。以下为口径与"为什么"。

## 基础画像（阶段 4）

| 指标 | 口径 | 为什么 |
|---|---|---|
| 会话规模 | 会话数 / 消息总数 / 工具调用总数 / 日期范围 / 模型分布 | 任务量级、是否可对比 |
| 任务形态 | 每会话用户消息数分布（1 = 单轮；≥2 = 多轮/人工介入） | **记忆行为的开关**：单轮不写、多轮才写 |
| 工具分布 | TOP 工具（terminal/execute_code/skill_view/memory…） | 主通道判断 |
| memory 调用 | 按 action 分布（add/replace/remove） | 写/改/删结构 |
| 快照版本 | 从 system_prompt 提取 MEMORY 块 → md5 指纹 → 版本数/按日演化/填充率 | 记忆是否在会话外被维护 |
| 时间节奏 | 每日会话量 / 每日写入量 | 业务波峰与记忆节奏 |

## 深度分析（阶段 5）

| 指标 | 口径 | 为什么（实测价值） |
|---|---|---|
| **写入成功率** | memory 调用后紧跟 tool 结果中 success:false 的比例；失败原因分类（超限/找不到目标/重复/空） | **最容易被漏的严重问题**：容量溢出时 73% 写入被拒 |
| 容量饱和 | 快照填充率分布（≥90% / ≥99% / 100% 满）；超限报错次数（"would exceed the limit"） | 记忆"饱和停摆"= 新经验写不进 |
| 重复写入 | 写入内容规范化（小写+去标点）后去重，完全相同者计数 | 缺"先查后写"，同一经验写 N 遍 |
| 写放大 | replace 的 old_text 归一化后，同一目标被改写次数；热条目（≥3 次） | 容量逼出的浓缩式更新，单条目承载过多 |
| 演化链 | 同一主题的连续 replace 按时间排开（old→new） | 记忆怎么长大（新增/合并/浓缩/删除） |
| 触发模式 | memory 调用距最近用户消息的步数（响应式 vs 自主式） | 写入依赖人工介入？ |
| 载体协同 | memory 调用前 3 步内出现 skill_manage 的次数；各载体读写频率 | 经验沉淀在哪个通道、是否失衡 |

## 口径注意

- **全量 vs 子集**：表格数字必须对应其声称的样本集（子集如"大搜相关 163"不能冒充全量 280）。
- **调用 vs 成功**：`938 次调用` ≠ `938 次写入`；必须区分"写入尝试"与"成功落盘"。
- **规范化去重**只抓"完全相同"的知识；语义同义（措辞不同）抓不到 → 报告如实标注是保守下界。
- **归因分离**：现象（描述性统计）可靠；归因（为什么）是合理推断，不写成因果定论。
