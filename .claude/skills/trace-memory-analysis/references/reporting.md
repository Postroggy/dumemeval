# 结论提炼与报告规范（阶段 7/8）

**目标读者是决策者。** 报告像专业分析，不像 AI 生成。

## 结论先行

- 报告开头就是「结论」区，不写背景铺垫（读者熟悉场景时背景是废话）。
- 每条发现 = **结论（callout 一句话）→ 证据（数字）→ 含义（一句）**。

## Callout 规范（Obsidian 风格，主流 md 阅读器兼容）

| 类型 | 用途 |
|---|---|
| `> [!abstract] 结论` | 总结论（分点列表现） |
| `> [!important] 关键事实` | 最重要的 2~3 条事实 |
| `> [!warning] / [!danger]` | 问题/严重问题（容量溢出、控制变量失败） |
| `> [!note]` | 中性事实（机制说明） |
| `> [!tip]` | 改进方向 / 建议 |

## Do / Don't

**Do：**
- 直接陈述现象、数据、结论；
- 正常现象不当发现（事后补记、回报延迟 = 人类正常时序，写了显得大惊小怪）；
- 结论边界写清（平台不同、非严格对照、描述性统计 vs 归因推断）；
- 机制准确（不凭直觉假设记忆如何读写）；
- 数字可复算、全量口径。

**Don't：**
- 写道歉/解释/弱化（"仅供参考""不构成定论""其实""可能"）；
- 对正常的事反复解释它为什么正常；
- 把推断当因果；
- 堆数字没结论，或只有结论没证据；
- 用子集数字冒充全量；
- 讲评测/框架私货（分析 trace 就是分析 trace）。

## 正式报告骨架

```
结论（callout：一句话 + 关键事实分点）
一、数据概况（表格 + 一句话来源说明）
二、核心发现（每条：结论 callout → 证据 → 含义）
三、深层机制总结（表格）
四、推理过程与结论边界（至少一个例子说明结论怎么推的 + 局限）
五、值得关注的改进方向（callout 分条，标注对应发现）
六、下一步计划（立即可做 / 需配合）
附录：关键指标速查 + 数据交付清单
```
