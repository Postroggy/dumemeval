# 独立验收问题修复

2026-09-15 的审查发现四处实现缺陷：Search 把上下文问题一起平均，未仅评分最终综合问题；
响应丢失后，重启的工具客户端为同一写操作生成了新身份；恢复已完成执行时再次调用评分器；
一个 mock CLI 固定样例缺少必需的 Java 环境变量。
此外，从零安装说明依赖作者机器的私有状态。
原始审查记录保留在 `results/independent-acceptance-20260915`。

## 修复设计

- Search 依据原始轮数定位最终问题。最终问题缺失或失败时，不报告官方分数。
  完整 query ID 在聚合时等权。
- 只依赖标准库的挂载客户端将待处理操作持久化并加锁，在确认响应前复用同一 ID，
  拒绝用另一个操作覆盖待处理状态。已有会话网关负责幂等投递。
- pipeline 中的评分器装饰器先记录评分尝试，再原子保存已完成、脱敏后的 BenchmarkResult。
  身份包含任务/执行证据、judge/数据配置、评分源码和依赖版本。
  状态不明的尝试停止，不自动重新评分。核心执行层没有引入 benchmark 分支。
- 独立复验还发现一次评分内部存在 SDK/verifier 隐式重试。
  现已关闭 SDK 重试，仅对明确拒绝的请求按策略重试；响应丢失和服务端错误保留为未测，
  不再触发一次推理。官方 worker 的工厂在发布新建的 Math/Phys 环境前配置 llm_backend SDK。
  这只修改通信设置，固定版本的官方源码、提示词和评分算法均未修改。
  JSON 请求身份使用规范序列化，保留布尔值与数字的差异。
  用户显式配置的 judge num_runs 属于计划内重复评判，与失败重试分开。
- 测试配置为 mock 不会真正启动的服务提供占位路径。
- 复现文档补全锁定版本的下载、镜像构建、代理登录/启动及隔离安装目录。
  凭据由运行者自行提供。
